## Demo laptop (MacBook Air) — getting the 5 notes onto it
The live notes are sidecars **next to the audio** in `ALLEGORY_MUSIC_DIR`. The
Mac's music folder won't have them until copied; they're in git at `curation/`.
On the MacBook, in Terminal:

```bash
cd ~/Repos/allegory     # wherever it's cloned (folder may still read jellyfin-sound-machine)
git pull                # gets curation/
MUSIC="$HOME/AllegoryMusic"   # EDIT: the ALLEGORY_MUSIC_DIR from .env.local

cp "curation/Lennon, John/John Lennon - John Lennon_Plas/03 I Found Out.md"       "$MUSIC/Lennon, John/John Lennon - John Lennon_Plas/"
cp "curation/Cave, Nick & The Bad Seeds/Ghosteen/02 Bright Horses.md"            "$MUSIC/Cave, Nick & The Bad Seeds/Ghosteen/"
cp "curation/Talking Heads/Remain In Light/04 Once In A Lifetime.md"             "$MUSIC/Talking Heads/Remain In Light/"
cp "curation/Young, Neil/Decade/07 Old Man.md"                                   "$MUSIC/Young, Neil/Decade/"
cp "curation/Dylan, Bob/1963_-_The__Freewheelin__Bob_Dylan/03_Masters_Of_War.md" "$MUSIC/Dylan, Bob/1963_-_The__Freewheelin__Bob_Dylan/"
```

- Destination folders must already exist (the songs present with the **same
  `Artist/Album/` layout** as the Fedora box). A "No such file or directory"
  error = that song's folder is named differently on the Mac; match it by hand.
- Unsure of the music path? `grep MUSIC ~/Repos/allegory/.env.local`.
- Then reopen Allegory / **Rescan** — the "missing notes" warning clears for all 5.

## Ollama CORS on the MacBook — the detailed version

**Read this first — it probably ends the confusion:** for the *demo* you may not
need to set `OLLAMA_ORIGINS` at all. Ollama **allows `localhost` / `127.0.0.1`
origins by default** (any port, http or https). Allegory runs at
`https://localhost:5173`, so it works against a stock Ollama with **nothing set**.
The *only* reason the Fedora box needed a value was to also allow **Marginalia**
at `https://ohiomathteacher.github.io` (a remote origin). If you won't use
Marginalia's local-model option *on the Mac*, the safest, simplest state is
**unset** — and the one thing to avoid is `OLLAMA_ORIGINS=*`.

Don't trust env vars over reality — **test what the running server actually
enforces.** That curl is the source of truth on every step below.

### Step 1 — check the current state (do this before changing anything)
```bash
# What a HOSTILE origin gets (this is what matters):
curl -s -D - -o /dev/null -H "Origin: https://evil.com" http://localhost:11434/api/tags | grep -i access-control
#   prints "Access-Control-Allow-Origin: *"  → WIDE OPEN, fix it (Step 2)
#   prints nothing                            → hostile origin already BLOCKED (good)

# What ALLEGORY's origin gets (must be allowed or the demo can't reach Ollama):
curl -s -D - -o /dev/null -H "Origin: https://localhost:5173" http://localhost:11434/api/tags | grep -i access-control
#   prints "...Allow-Origin: https://localhost:5173" (or a localhost variant) → Allegory is covered
```
**If evil.com is blocked AND localhost is allowed, you are DONE — stop here.**
That's the common good state with `OLLAMA_ORIGINS` simply unset. Don't fight
launchctl.

### Step 2 — only if you must change it
First find HOW Ollama runs — that picks the method:
```bash
brew services list | grep ollama     # a Homebrew service?
pgrep -fl ollama                     # or Ollama.app / `ollama serve`
```

**A) Homebrew service** (most likely here — HARDWARE.md says "Ollama (Homebrew)"):
```bash
# Fix a wide-open OLLAMA_ORIGINS=* by removing it (fall back to the safe localhost default):
launchctl unsetenv OLLAMA_ORIGINS
brew services restart ollama

# OR set the allowlist (only if you need github.io too):
brew services stop ollama
launchctl setenv OLLAMA_ORIGINS "https://localhost:5173,https://ohiomathteacher.github.io"
brew services start ollama
```
A `brew upgrade` can regenerate the service plist — re-check after upgrading.

**B) Ollama.app (menu-bar app):**
```bash
launchctl setenv OLLAMA_ORIGINS "https://localhost:5173,https://ohiomathteacher.github.io"
```
Then **fully Quit** Ollama from the menu bar (not just close) and relaunch.
`launchctl setenv` does NOT survive a reboot for the app — for a one-off demo
that's fine, or just leave it unset and rely on the localhost default.

**C) Manual `ollama serve`:** export it in the shell you launch from:
```bash
export OLLAMA_ORIGINS="https://localhost:5173,https://ohiomathteacher.github.io"
ollama serve
```

### Step 3 — verify (re-run the Step 1 curls)
You want evil.com → nothing, localhost:5173 → allowed. Same on every path.

(On Fedora this is done via a systemd drop-in: `OLLAMA_ORIGINS=https://localhost:5173,https://ohiomathteacher.github.io`.)
